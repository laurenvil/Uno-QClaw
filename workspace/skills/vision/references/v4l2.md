# V4L2 — low-level camera and codec access on the Uno Q

Linux exposes the camera sensors and the GPU video codecs as **V4L2 (Video4Linux2)** devices at `/dev/video*`. This is the foundation that OpenCV, GStreamer, FFmpeg, and any custom C/C++ camera code build on.

## Enumerate devices

```bash
v4l2-ctl --list-devices
```

Typical output on the Uno Q:

```
qcom-camss (platform:1b0ac00.qcom_camss):
        /dev/video0       # camera sensor 0 (front ISP)
        /dev/video1       # camera sensor 1 (rear ISP)

Qualcomm Camera Codec Encoder (platform:1d40000.video-codec-enc):
        /dev/video10
Qualcomm Camera Codec Decoder (platform:1d40000.video-codec-dec):
        /dev/video11
```

Numbering can vary across kernel updates — always re-run `v4l2-ctl --list-devices` rather than hardcoding `/dev/video0`.

## Inspect supported formats

```bash
v4l2-ctl --device /dev/video0 --list-formats-ext
```

Lists every (format, resolution, frame rate) combination the device supports. Common entries: NV12, YUYV, JPEG.

## Inspect current settings

```bash
v4l2-ctl --device /dev/video0 --all
```

Shows the active format, resolution, frame rate, and every tunable control (exposure, gain, white balance).

## Adjust a control

```bash
# List all controls
v4l2-ctl --device /dev/video0 --list-ctrls

# Set exposure (example — actual control name depends on sensor)
v4l2-ctl --device /dev/video0 --set-ctrl exposure_absolute=200
```

## Capture a single frame to a file

```bash
v4l2-ctl --device /dev/video0 \
    --set-fmt-video=width=1280,height=720,pixelformat=NV12 \
    --stream-mmap --stream-count=1 \
    --stream-to=frame.yuv
```

Or, for an immediately-viewable JPEG:

```bash
gst-launch-1.0 v4l2src device=/dev/video0 num-buffers=1 \
    ! jpegenc ! filesink location=frame.jpg
```

(See `gstreamer.md` for the full pipeline reference.)

## Open the device from Python (raw V4L2)

The `v4l2-python3` library exposes V4L2 ioctls directly. For most projects use OpenCV or GStreamer instead — V4L2 raw is verbose and easy to get wrong.

```python
import v4l2py

with v4l2py.Device.from_id(0) as cam:
    cam.controls.brightness.value = 50
    for i, frame in enumerate(cam):
        if i == 0:
            with open("frame.raw", "wb") as f:
                f.write(bytes(frame))
            break
```

## Hardware codec devices

| Device | Purpose | GStreamer element |
|---|---|---|
| `/dev/video10` (typical) | Hardware video encoder | `v4l2h264enc`, `v4l2h265enc` |
| `/dev/video11` (typical) | Hardware video decoder | `v4l2h264dec`, `v4l2h265dec`, `v4l2vp9dec` |

You don't talk to these directly — use GStreamer, which selects them automatically when you instantiate the `v4l2h*` elements.

## Diagnostics

| Symptom | Check |
|---|---|
| `v4l2-ctl --list-devices` is empty | `dmesg | grep -i camss` — kernel may have failed to bind the camera driver |
| Device exists but reads return zero bytes | `v4l2-ctl --device /dev/video0 --stream-mmap --stream-count=1` to bypass framework bugs |
| `cv2.VideoCapture(0)` blocks forever | Camera might be in use by another process; `fuser /dev/video0` to identify |
| Frame rate lower than spec | `v4l2-ctl --get-parm` and `--set-parm` to set the requested rate |
